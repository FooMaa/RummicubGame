## Результат проверки

**Сквозная проверка облачного API пока не прошла.** Функция получила статус ACTIVE, но `/health` API Gateway возвращает 502. Отдельная минимальная диагностическая Java-функция без YDB также вернула 502. Прямое TCP-подключение к `functions.yandexcloud.net:443` отклоняется, чтение журналов возвращает `Unavailable`. В консоли показано предупреждение об ограниченной работе платформы. Диагностический маршрут убран; основная интеграция закреплена на теге `game`.

Это признаки проблемы доступности платформы, но они не заменяют сквозную проверку приложения после восстановления сервиса. Регистрацию и полноценную партию через публичный адрес пока нельзя считать проверенными.

## Сохранение состояния

Для небольшой компании используется ограниченный JSON-снимок всего состояния. YDB читает и обновляет одну строку в сериализуемой транзакции. Только подтверждённый ABORTED безопасно повторяется; неопределённый исход commit не повторяется автоматически. HTTP-ответ об успехе выдаётся после commit.

SQLite внутри функции используется как временный рабочий кэш. Перед каждым запросом он восстанавливается из YDB; его файл не считается постоянным хранилищем. В снимке сохраняются аккаунты (PBKDF2), хеши сессий, комнаты и лимит попыток входа. Чужие подставки клиентам не передаются.

Облачный режим ограничен 20 комнатами и снимком 256 КиБ. Это решение для небольшой компании, не для большого числа игроков. При росте нагрузки нужно разнести пользователей, сессии и комнаты по отдельным строкам/таблицам YDB, сохранив транзакционность входа в комнату и хода.

Боты и просроченные ходы продвигаются при запросах состояния. Постоянный фоновый процесс в облаке не требуется. Когда все клиенты закрыты, партия сохраняется и продолжает обработку при возвращении. В обычном режиме отдельного сервера прежний фоновый таймер сохранён.

## Проверки

- 18 локальных тестов прошли: правила, полные партии ботов, API, восстановление, два экземпляра сервера и имитация отказа commit.
- Отдельный opt-in тест на настоящей YDB успешно проверил конкурентное увеличение состояния из двух клиентов. Он использует изолированную строку `test-UUID` и удаляет её после проверки.
- Android Lint: без замечаний. APK с HTTPS-адресом собран и проверен по подписи, целостности и выравниванию.
- Локальный обработчик CloudFunction, подключённый к настоящей YDB с временным IAM-токеном CLI, прошёл регистрацию, создание комнаты, добавление бота, старт, чтение состояния, выход и отзыв сессии. Созданные им тестовые аккаунты и сессии удалены по их точным идентификаторам. Это не проверка запуска в среде Cloud Functions.
- Подписанный release APK 1.0.1 установлен начисто и запущен на Android Emulator API 34. На физическом Samsung S25 он пока не проверен.

Обычная проверка:

```bash
./gradlew :core:test :server:test :server:functionZip :app:lintDebug :app:assembleDebug
```

Live-тест требует `RUMMI_LIVE_YDB=1`, `YDB_CONNECTION_STRING` и штатной аутентификации YDB SDK. Токены не выводятся в логи.

## Повторное развёртывание

```bash
source data/yandex-deployment.env
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
./scripts/deploy-yandex.sh
```

Скрипт пересобирает код и тесты, загружает ZIP в существующий приватный бакет, публикует версию с тегом `game`, обновляет существующий API Gateway и проверяет `/health`. Не создаёт новые ВМ, реестры образов и сервисные аккаунты. При неуспешной проверке завершается с ошибкой, не объявляя размещение рабочим.

## Стоимость

Free tier — бесплатный объём, а не гарантия нулевого счёта. Учитываются вызовы/вычисления Cloud Functions, вызовы API Gateway, операции YDB, объекты и логи. Нет оплачиваемой резервной мощности YDB и прогретых экземпляров функции. Бюджетные уведомления сами по себе не останавливают расход. После восстановления нужна оценка потребления реальной партии.

Старый Container Registry не используется: сервис закрывается для новых подключений. Java-пакет загружается напрямую в Cloud Functions через Object Storage.
