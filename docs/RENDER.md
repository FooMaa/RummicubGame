# Render Free + YDB

Сервер развёрнут 29 октября 2026 года на тарифе **Free** во Франкфурте:

- API: https://rummiclub.onrender.com
- Проверка доступности: https://rummiclub.onrender.com/health
- Репозиторий: https://github.com/FooMaa/RummicubGame, ветка `main`.
- Способ запуска: Dockerfile из корня, порт из переменной `PORT`, health check `/health`.

## Хранение и доступ

При заданной `YDB_CONNECTION_STRING` сервер использует транзакционный снимок в существующей YDB Serverless. SQLite — временный кэш. Сон, смена контейнера и потеря локального диска Render не удаляют сохранённые аккаунты и партии.

Отдельный аккаунт `rummiclub-render` имеет `ydb.editor` только на базе игры. Его авторизованный ключ хранится в Render Secret File `rummiclub-ydb-key.json`; переменная `YDB_SERVICE_ACCOUNT_KEY_FILE_CREDENTIALS` указывает на `/etc/secrets/rummiclub-ydb-key.json`. Ключи не включаются в Git и Docker-образ. `JAVA_TOOL_OPTIONS=-XX:MaxRAMPercentage=60.0` ограничивает долю памяти для Java heap.

Облачный режим рассчитан на небольшую компанию: максимум 20 комнат и снимок 256 КиБ. Для роста потребуются отдельные строки пользователей, сессий и комнат.

## Проверки

Публичный API прошёл регистрацию двух тестовых игроков, создание комнаты, присоединение второго игрока, добавление бота, старт, проверку скрытых подставок и ход. После ручного Restart service в журнале появился новый экземпляр; прежняя сессия, комната и подставка восстановились. Тестовая комната и сессии после проверки удалены/отозваны.

Права нового сервисного аккаунта отдельно проверены конкурентным тестом на настоящей YDB с изолированной тестовой строкой. Локальные тесты движка, сервера, Android-клиента и Android Lint прошли.

APK 1.0.2 содержит адрес Render по умолчанию. Перед первым запросом к `*.onrender.com` клиент безопасно повторяет GET `/health` до 120 секунд; игровые POST-запросы автоматически не повторяются. Возврат в меню отменяет ожидание, а офлайн-боты работают в отдельном потоке. Если в старом приложении уже сохранён другой адрес, замените его в настройках на адрес выше.

## Обновления

Публикуйте код в `main`, затем в Render выберите **Manual Deploy → Deploy latest commit**. Подключение сделано через публичный Git URL, без выдачи Render прав на весь GitHub-аккаунт. После обновления проверяйте `/health` и вход в комнату. Тариф оставляйте Free.

Для воспроизводимого нового развёртывания предусмотрен `render.yaml`. Ключ базы добавляется отдельно как Secret File. Обновление Android APK выполняется существующим GitHub Actions workflow; без signing secrets он собирает установочный debug APK. Локальный release подписывается постоянным ключом вне репозитория.

## Бесплатные квоты

Render Free засыпает после 15 минут без запросов; пробуждение обычно занимает около минуты. Даётся 750 часов на workspace в месяц. Постоянный диск и временная бесплатная PostgreSQL не используются. База остаётся в YDB с отдельными квотами. Сверх квот возможны расходы или приостановка сервиса; необычно большой исходящий трафик к внешней базе также может привести к приостановке Free-сервиса. Полноценный тест после 15 минут простоя пока не проводился; ожидание проверено модульными тестами и запуском нового контейнера.

Источники: [Render Free](https://render.com/docs/free), [Render Secret Files](https://render.com/docs/configure-environment-variables#secret-files), [бесплатные квоты Yandex Cloud](https://yandex.cloud/ru/docs/billing/concepts/serverless-free-tier).

## Диагностика подключения Android 1.0.3

На телефоне пользователя `/health` открывается в браузере, но клиент 1.0.2 сообщает общую ошибку. Сервер после холодного запуска отвечает на `/health` и API. Причина отказа именно на телефоне пока не установлена.

Версия 1.0.3 сохраняет причину ошибки readiness, различает DNS/TLS/таймаут/отказ TCP и показывает постоянный диалог с адресом сервера. Во время запроса виден счётчик ожидания и отмена. Текст «повторяем подключение» убран для действий, которые автоматически не повторяются. Секреты, пароли и тела запросов в диагностике не выводятся. Для дальнейшего исправления нужен код ошибки из этого диалога на телефоне.

## DNS fallback Android 1.0.4

Пользователь подтвердил код DNS при доступном `/health` в браузере телефона. В 1.0.4 транспорт заменён на OkHttp; при UnknownHostException для публичного имени `*.onrender.com` используется Google DNS-over-HTTPS с bootstrap-адресами самого DNS-резолвера. IP игрового сервера не закреплён в APK. Для других доменов и локальных адресов публичный fallback не используется. Google получает только публичное имя сервера, без сессий и игровых данных. TLS и проверка имени сертификата сохранены.

Весь запрос имеет жёсткий срок ожидания, включая зависшее разрешение DNS; отмена закрывает сетевой вызов. Автоматическое повторение разрешено только для проверки готовности GET. POST-запросы игры одноразовые, редиректы отключены. Ошибка дополнительно указывает фазу: проверка `/health` или игровой запрос.

Проверены 13 тестов клиента, включая принудительно сломанный системный DNS с настоящим HTTPS-подключением к Render, обрыв после получения POST, отсутствие переноса Authorization через редирект, лимит ответа и отмена. Физический Samsung требует повторной проверки после обновления.

Источники: [Google DoH](https://developers.google.com/speed/public-dns/docs/doh), [OkHttp](https://github.com/square/okhttp).
