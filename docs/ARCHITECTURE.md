# Архитектура

## Разделение ответственности

Android-приложение и сервер используют один модуль `core`. В локальной игре `Game` хранится на устройстве; в сетевой — только на сервере. `Room.View` содержит собственную подставку, открытый стол, количество чужих фишек и общую информацию. Банк и чужие подставки не сериализуются в ответ клиенту.

Каждая фишка имеет неизменный ID 0–105. Номер и цвет определяются ID, поэтому клиент не может подменить номинал фишки. Два экземпляра одного номинала имеют разные ID. Джокеры — 104 и 105. Порядок в последовательности значим: позиция джокера задаёт заменяемое число.

## Ход как атомарная операция

Клиент редактирует копию стола. Запрос `play` содержит всю новую раскладку и ожидаемую `revision`. Сервер проверяет очередь, ревизию, каждую комбинацию, уникальность ID, происхождение всех новых фишек, сохранение всех старых, обязательную выкладку хотя бы одной своей фишки и условия первого выхода. Сначала валидируется весь ход, затем меняется состояние.

Комната копируется перед изменением. SQLite записывает новую версию, и только после успеха сервер публикует её в памяти. Ошибка записи не публикует частично применённый ход. Команды и таймер сериализованы под одним монитором. Повторная отправка после потери ответа не может дважды применить ход: старая ревизия отклоняется.

`edit` отмечает незавершённый черновик для штрафа по таймеру. Сброс черновика снимает отметку. Это UX-флаг, а не доверенный механизм защиты от модифицированного клиента; все проверки раскладки всегда серверные. При истечении времени до обработки запроса сервер сначала завершает просроченный ход. Нет таймера — нет автоматического пропуска.

## Соединение и жизненный цикл

Состояние запрашивается каждые 1,5 секунды, пока открыт стол/лобби. Сервер отправляет небольшой полный snapshot, поэтому восстановление не зависит от истории событий. Неизменная ревизия не сбрасывает локальный черновик. Смена хода сбрасывает устаревший черновик. После background/resume повторяется синхронизация. Сетевая ошибка показана в статусе; действия автоматически не повторяются.

Боты работают на сервере через 1–2 секунды после начала своего хода и не зависят от подключённого хозяина. Ушедший через `leave` игрок заменяется ботом; при сетевом обрыве он остаётся участником и подчиняется выбранному таймеру. Активные комнаты и сессии переживают рестарт. Комнаты без людей удаляются; комнаты без изменений очищаются через 7 дней.

## Аккаунты

Уникальный логин — имя в нижнем регистре, 3–24 символа. Пароли хешируются PBKDF2-HMAC-SHA256 (210 000 итераций, случайная 128-битная соль). Сессия — случайные 256 бит, в БД хранится SHA-256 токена, срок 30 дней. Пароли и токены не логируются. Android сохраняет токен в AES-GCM с ключом Android Keystore, backup выключен. Logout отзывает конкретную сессию.

Запросы ограничены 64 KiB, очередь обработчиков ограничена; на auth действует лимит по IP. За reverse proxy лимит видит IP прокси и общий для всех его клиентов; перед публичным запуском с большой аудиторией следует вынести rate limiting в доверенный edge и настроить политику адресов. Приложение не следует HTTP-редиректам с bearer-токеном.

## Границы текущей версии

Один серверный процесс, SQLite, до 1000 комнат. Глобальная блокировка упрощает консистентность, но не предназначена для массовой нагрузки. Следующий этап масштабирования — отдельные очереди комнат, база аккаунтов PostgreSQL и доставка событий через WebSocket. Такой переход не меняет правила `core`.

Бот ограничен 18 000 узлов поиска, использует только публичный стол и свою руку. Он выбирает комбинации и расширения, но может пропустить сложный ход с перестройкой чужих рядов. Сложность одна. Hint-кнопка не имитирует «умный AI».

Нужные для коммерческого сервиса функции — восстановление аккаунта, верификация адреса, удаление аккаунта, наблюдаемость, нагрузочные тесты, политика обработки данных и администрирование — не реализованы. Release сейчас предназначен для прямой установки, а не для публикации в Google Play; перед публикацией потребуется актуализировать требования магазина и target SDK.
